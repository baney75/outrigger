# Privacy

Outrigger connects directly to the T3 Code server you pair. It has no Outrigger account, telemetry, advertising SDK, or vendor backend. This page describes the extension's own behavior; your T3 Code server and any agent provider it uses have separate policies.

| Data                               | When it is used                                            | Where it goes or stays                                                                                                                                                                                                                                                  |
| ---------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pairing link and bearer credential | You paste a link to connect                                | The one-time token is exchanged with the chosen T3 server. The resulting bearer credential is saved in `chrome.storage.local` and used by the background worker for that server. It is not sent to the panel state.                                                     |
| Session list and recent messages   | While connected                                            | Fetched from the paired T3 server and shown in the extension. T3 remains the source of truth.                                                                                                                                                                           |
| Message or request response        | You press **Send** or answer a request                     | Sent to the paired T3 server. A draft stays local until that action. Outrigger does not automatically replay an uncertain send.                                                                                                                                         |
| Drafts and attached context        | You type or press **Attach page**                          | Saved locally per server and session. On send, the text and any attached context go to the paired T3 server as one message.                                                                                                                                             |
| Page title, URL, selected text     | You press **Attach page** on the current tab               | Only the previewed attachment is saved with the draft. The URL must be HTTP(S); credentials, query, and fragment are stripped. The title is limited to 300 characters and selected text to 12,000. The URL path and selected text can still contain sensitive material. |
| Preferences and attention ledger   | You choose a theme, watch a session, or change silent mode | Saved locally. The ledger prevents duplicate attention alerts. OS notifications contain a generic prompt, without conversation text.                                                                                                                                    |

Outrigger does **not** scan tabs in the background or collect browsing history. The `activeTab` and `scripting` permissions allow the explicit **Attach page** action. Permission to access a T3 server origin is requested when pairing; notification permission is requested only when you turn off the default silent mode. The manifest declares possible host patterns, but the extension requests the chosen origin at pairing time.

`chrome.storage.local` is browser profile storage, **not an encrypted vault**. Protect the browser profile and machine. To remove local connection state and drafts, use **Settings → Disconnect and clear local drafts**. If a credential might be compromised, also revoke its session in T3 Code. The extension cannot erase messages already sent to the server or to an agent provider.

Imported themes are parsed as color data. Outrigger does not execute imported CSS or load remote message images. For implementation detail, see [architecture](architecture.md) and [security](../SECURITY.md).
